# Authentication redirect configuration

HEYTU uses two different redirect layers. Google always sends the OAuth
response back to the callback URL shown in the Supabase Google provider
settings. Supabase then sends the user to the app URL supplied at sign-in.

## Local web

- App redirect sent to Supabase: `http://localhost:8081`
- Add that URL to Supabase **Authentication → URL Configuration → Redirect
  URLs**.
- Add `http://localhost:8081` as a Google Cloud **Authorized JavaScript
  origin**.
- Google Cloud **Authorized redirect URI**: the exact Supabase callback shown
  in the project's Google provider settings (normally
  `https://<PROJECT-REF>.supabase.co/auth/v1/callback`).

## Production web / Vercel

- App redirect: `https://<YOUR-HEYTU-DOMAIN>` (the final HTTPS site origin).
- Add the exact origin to Supabase **Redirect URLs** and Google Cloud
  **Authorized JavaScript origins**.
- Google Cloud **Authorized redirect URI** stays the Supabase callback shown
  in the dashboard. It is not the Vercel domain.
- Do not add a guessed Vercel domain. Replace the placeholder after the owner
  selects the production domain.

## Native Expo

- The app config already declares the `heytu` scheme.
- Native return URL generated by the app: `heytu://auth/callback`.
- Add that exact URI to Supabase **Redirect URLs**.
- Google Cloud still uses the Supabase callback URI as its authorized redirect
  URI. The native deep link is the Supabase-to-app redirect, not Google's
  callback.
- Use an Expo development or production build to validate native callbacks;
  Expo Go may use a different generated redirect and must be separately
  allow-listed if used for auth testing.

The running app sets the web redirect to the current origin and uses Expo
Linking with the configured scheme on native. No production hostname or
Supabase project reference is hard-coded.
